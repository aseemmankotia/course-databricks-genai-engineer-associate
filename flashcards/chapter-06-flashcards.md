## Chapter 6: Packaging and Serving with MLflow and Model Serving — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | MLflow langchain flavor vs pyfunc flavor: when to use each for GenAI models? | langchain flavor: Use when model IS a LangChain chain/agent—auto-captures dependencies, LangChain version, chain structure. pyfunc flavor: Use for custom logic, non-LangChain models, or when you need maximum flexibility with custom Python class. Exam tip: If question says 'LangChain chain', use langchain flavor unless custom wrapper is explicitly needed. |
| 2 | Unity Catalog model registry: what are the three levels in the namespace? | catalog.schema.model (e.g., prod_catalog.genai_models.chatbot_v1). Exam tip: Three-level naming automatically uses Unity Catalog registry. Two-level naming (workspace.model) uses legacy Workspace Model Registry. Questions often test which registry is being used based on naming format. |
| 3 | MLflow model registration command: register model from run_id 'abc123' to Unity Catalog path 'prod.ml.model_v1' | mlflow.register_model(model_uri='runs:/abc123/model', name='prod.ml.model_v1'). Exam tip: model_uri format is 'runs:/<run_id>/model' (not 'experiments/...'). Name uses three-level namespace for Unity Catalog. |
| 4 | Databricks Model Serving compute sizes and when to use each? | Small: Low-traffic, development, cost-sensitive. Medium: Production workloads, moderate traffic. Large: High-traffic, low-latency requirements, complex models. Exam tip: Questions test cost vs performance trade-offs. Small = cheapest but slowest; Large = fastest but most expensive. |
| 5 | Model Serving scale-to-zero: what happens and when is it NOT recommended? | Scale-to-zero: endpoint scales to 0 instances during idle periods (saves cost), but causes cold start delay (30-60s) on first request after idle. NOT recommended when: low-latency SLAs required, or traffic is unpredictable spiky patterns. Exam tip: Trade-off is cost savings vs cold start latency. |
| 6 | Model Serving endpoint URL format for REST API queries? | https://<workspace-url>/serving-endpoints/<endpoint-name>/invocations. POST request with Authorization: Bearer <token> header. Body format: {'dataframe_records': [{'input': 'value'}]} for pandas input or {'inputs': [...]} for tensors. Exam tip: /invocations path is required, not /predict. |
| 7 | Unity Catalog model aliases: purpose and common examples? | @champion, @challenger, @staging, @production (custom names allowed). Aliases point to specific versions, enable version switching without code changes. Exam tip: Aliases support A/B testing via traffic splitting. @champion/@challenger pattern is common for gradual rollout questions. |
| 8 | MLflow Deployments: what is it and when to use vs Model Serving? | MLflow Deployments (formerly Gateway): wraps external LLM APIs (OpenAI, Anthropic, Cohere) as MLflow endpoints for governance/cost tracking. Use when: integrating external APIs, need centralized credential management. Model Serving: deploys MLflow-logged models. Exam tip: External API = Deployments; MLflow-logged model = Model Serving. |
| 9 | Code to query Model Serving endpoint 'my-endpoint' using Python requests library? | import requests url = 'https://<workspace>.cloud.databricks.com/serving-endpoints/my-endpoint/invocations' headers = {'Authorization': f'Bearer {token}'} data = {'dataframe_records': [{'prompt': 'test'}]} response = requests.post(url, json=data, headers=headers). Exam tip: Must include /invocations path and Bearer token. |
| 10 | Model Serving autoscaling: what does min_instances and max_instances control? | min_instances: minimum active instances (0 = scale-to-zero enabled, ≥1 = always warm). max_instances: maximum instances during high traffic. Exam tip: min=1 eliminates cold starts but costs more than min=0. Questions test when to use min=0 (cost priority) vs min≥1 (latency priority). |
| 11 | Creating new model version in Unity Catalog: what happens if model name doesn't exist vs already exists? | Name doesn't exist: mlflow.register_model() creates NEW model AND version 1. Name exists: creates NEW VERSION (increments version number). Exam tip: Same register_model() call handles both cases. No separate API for 'add version' vs 'create model'. |
| 12 | Model Serving traffic splitting: how to configure A/B test with 80% to version 3, 20% to version 5? | Set aliases (e.g., @champion → v3, @challenger → v5), then configure endpoint traffic config: {'@champion': 80, '@challenger': 20}. Server-side splitting at endpoint level. Exam tip: Percentages must sum to 100. Splitting uses aliases or version numbers, not model names. |
