## Chapter 2: Preparing Data for RAG on Databricks — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is the typical chunk overlap percentage for RAG systems? | 10-20% overlap. Common values: 10% for simple content, 15-20% for complex content where context continuity matters. Exam tip: Overlap prevents splitting concepts across chunks but increases storage; >25% is rarely justified. |
| 2 | Fixed-size chunking vs Recursive chunking — when to use each? | Fixed: simple documents, uniform structure, speed priority (blogs, articles). Recursive: documents with hierarchy, respects natural boundaries (paragraphs, sections), better context preservation. Exam tip: Recursive is default best practice unless simplicity or speed is critical. |
| 3 | What happens if chunk size is too small in RAG? | Loss of context — individual chunks lack enough information to answer questions. Symptoms: LLM says 'insufficient context', answers require synthesizing too many chunks. Exam tip: <256 tokens rarely sufficient except for very focused retrieval (definitions, facts). |
| 4 | What happens if chunk size is too large in RAG? | Retrieval of irrelevant content — chunks contain multiple topics, reducing precision. Symptoms: retrieved chunks have right answer buried in noise, LLM gets distracted. Exam tip: >2048 tokens often too large; sweet spot 512-1024 for most use cases. |
| 5 | Required Delta table columns for Vector Search source? | Minimum: id (unique identifier), embedding (ARRAY<FLOAT>). Recommended: text (original chunk text), metadata columns for filtering. Exam tip: 'embedding' must be ARRAY<FLOAT> or ARRAY<DOUBLE>; Vector Search reads this column name by convention. |
| 6 | How does Databricks Vector Search sync with source Delta table? | Uses Delta Change Data Feed (CDF) for incremental sync. Must enable: ALTER TABLE SET TBLPROPERTIES (delta.enableChangeDataFeed = true). Exam tip: Without CDF, index requires manual refresh or rebuild; CDF enables automatic incremental updates. |
| 7 | Semantic chunking vs Fixed/Recursive — key difference? | Semantic chunking splits based on topic/meaning changes (using embeddings to detect semantic boundaries), not fixed size or syntax. Result: variable-sized chunks aligned to concepts. Exam tip: Best for documents with clear topic shifts; more compute-intensive than fixed/recursive. |
| 8 | What is a data quality filter for chunk preprocessing? | Removing low-quality chunks BEFORE indexing: chunks <50 chars (headers, page numbers), high similarity to boilerplate, non-language content. Exam tip: Filtering pre-index improves retrieval precision; filtering post-retrieval wastes compute and storage. |
| 9 | BGE vs E5 embedding models on Databricks — when to choose each? | BGE (BAAI General Embedding): state-of-the-art English retrieval, best for technical/domain-specific content. E5: strong multilingual support, choose for multi-language RAG. Exam tip: For English-only, BGE outperforms; E5 trades English accuracy for multilingual capability. |
| 10 | Why add metadata columns to chunk Delta table? | Enables filtered retrieval: filter by doc_source, date, category BEFORE vector search to reduce search space and improve relevance. Example: 'search only 2024 docs' or 'search only product manuals'. Exam tip: Metadata filtering (pre-filter) is faster and more accurate than post-filter. |
| 11 | What is the impact of using OpenAI embeddings via API vs. Databricks-hosted embeddings? | API: adds latency (200-500ms network), external dependency, per-token cost. Databricks-hosted (BGE, E5): low latency (<100ms), no external calls, included in DBU cost. Exam tip: Choose API only if accuracy gain justifies latency/cost; otherwise host on Databricks. |
| 12 | How to handle tables in PDF extraction for RAG? | Use table-aware extraction libraries (pdfplumber, Camelot, or OCR with layout analysis). Convert tables to readable text format (markdown tables or key-value pairs). Exam tip: Standard PDF text extraction (PyPDF2 basic mode) often scrambles table data; use specialized tools. |
