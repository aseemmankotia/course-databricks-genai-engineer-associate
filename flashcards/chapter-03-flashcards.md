## Chapter 3: Building RAG Applications with Vector Search — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Databricks Vector Search similarity_search: what are the 3 core parameters? | query_vector (embedding array), num_results (int, top-k), filters (dict, metadata filtering). Exam tip: No built-in score_threshold parameter—filter results manually after retrieval. |
| 2 | Higher num_results in Vector Search affects precision and recall how? | Higher num_results = MORE recall (find more relevant docs) but LOWER precision (more noise/irrelevant docs). Lower num_results = higher precision but may miss relevant docs. Exam tip: Balance with similarity threshold filtering. |
| 3 | Similarity score threshold: set higher (0.9) or lower (0.5) for maximum recall? | LOWER threshold (0.5) = more recall (retrieves more docs, including lower-similarity ones). Higher threshold (0.9) = higher precision (only very similar docs). Exam tip: Lower threshold retrieves more but includes noise. |
| 4 | Vector Search filters parameter syntax for metadata filtering: equality and comparison operators? | Equality: {'field': 'value'}. Comparison: {'field': {'$gt': value, '$gte': value, '$lt': value, '$lte': value}}. AND multiple conditions: include in same dict. Exam tip: MongoDB-style syntax, NOT SQL strings. |
| 5 | RAG prompt template: What are the 3 essential components? | 1) System prompt (grounding instructions, behavior rules). 2) Retrieved context (injected docs/chunks). 3) User query. Exam tip: Order matters for some models—typically system → context → query. |
| 6 | How to reduce hallucination in RAG with prompt engineering (2 techniques)? | 1) Explicit grounding: 'Only use provided context, cite sources'. 2) Fallback instruction: 'Respond "I don't have enough information" if context insufficient'. Exam tip: Grounding instructions are the PRIMARY hallucination mitigation—tested heavily. |
| 7 | Cross-encoder reranking in RAG: primary benefit and tradeoff? | Benefit: Higher precision (scores query-doc pairs more accurately than vector similarity). Tradeoff: Adds significant LATENCY (N forward passes through transformer). Exam tip: Reranking improves ordering, NOT recall. |
| 8 | Vector Search filters: Can you filter on similarity score directly? | NO. The 'filters' parameter is for metadata fields only (e.g., doc_category, date). Similarity score filtering must be done manually after retrieval in application code. Exam tip: Common wrong answer—filters parameter does NOT filter by score. |
| 9 | When does increasing num_results NOT improve recall? | When relevant documents aren't in the vector index at all, or when embedding quality is poor (semantic mismatch). Increasing num_results only helps if relevant docs exist but are ranked beyond current top-k. Exam tip: num_results is retrieval parameter—doesn't fix embedding problems. |
| 10 | RAG citation requirement: How to make LLM cite source documents in response? | Include source metadata (doc ID, title, section) in retrieved context. Add system prompt instruction: 'Cite the document ID/section for each fact'. Exam tip: Citation is prompt engineering, not a post-processing or retrieval setting. |
| 11 | num_results=5 vs num_results=20: which has higher PRECISION (fewer irrelevant docs)? | num_results=5 has higher precision (top 5 are most similar, less noise). num_results=20 includes lower-ranked docs with more irrelevant content. Exam tip: Precision/recall tradeoff—lower k = precision, higher k = recall. |
| 12 | What happens if RAG system prompt is too strict about saying 'I don't know'? | Model refuses to answer even when partial/useful information exists in context. Balance needed: acknowledge limitations but still use available context. Exam tip: Overly strict grounding can reduce usefulness—test common scenario. |
