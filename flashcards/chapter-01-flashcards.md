## Chapter 1: Designing GenAI Applications on Databricks — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | When should you choose RAG over fine-tuning? | RAG when: (1) Knowledge changes frequently and needs real-time updates, (2) Need citations/sources, (3) Limited labeled training data, (4) Knowledge is external/factual rather than style/format. Exam tip: Look for 'frequently updated documents' or 'cite sources' as RAG indicators. |
| 2 | When should you choose fine-tuning over RAG? | Fine-tuning when: (1) Have 1,000+ labeled examples of desired behavior, (2) Need consistent style/format/tone, (3) Task requires learning patterns not just retrieving facts, (4) Specialized domain language/jargon. Exam tip: 'Consistent format' and 'large labeled dataset' signal fine-tuning. |
| 3 | What are the core components of a compound AI system with retrieval? | Retriever (fetches candidates from knowledge base), Reranker (re-scores for relevance/precision), Generator (LLM creates response from top results), Orchestrator (manages flow). Exam tip: Reranker often overlooked but critical for accuracy in large knowledge bases. |
| 4 | What distinguishes an agent from a standard LLM application? | Agent has: (1) Tool-calling capability (invoke external functions/APIs), (2) Multi-step reasoning (iterative decision-making), (3) Memory (maintains state across turns). Standard LLM: single-pass generation. Exam tip: 'API calls' or 'multi-step tasks' indicate agent needed. |
| 5 | When is a reranker component necessary in RAG? | Reranker needed when: (1) Initial retrieval returns 50+ candidates, (2) Multi-hop questions requiring synthesis, (3) Large knowledge base (>100K documents) where vector search precision drops. Reranker improves top-10 quality. Exam tip: Large corpus + complex queries = reranker required. |
| 6 | What Databricks model should you choose for high-throughput API serving with JSON output? | DBRX Instruct with GPU Model Serving and response_format parameter. DBRX optimized for instruction following, GPU handles throughput, response_format guarantees valid JSON. Exam tip: Structured output + high throughput = DBRX with response_format, not prompt parsing. |
| 7 | What tools should an agent have for SQL generation from natural language? | Essential tools: (1) Schema introspection (get table/column metadata), (2) Query validator (check syntax/schema compatibility), (3) SQL executor (run validated queries). Exam tip: Schema tool must come before executor to validate against actual schema. |
| 8 | What guardrails are required for an agent calling external payment APIs? | Required guardrails: (1) Input validation (prevent injection attacks), (2) Amount limits (prevent excessive charges), (3) Confirmation prompts (human approval for transactions), (4) Rate limiting (prevent abuse). Exam tip: Financial actions always need human-in-loop confirmation. |
| 9 | When should you use prompt engineering instead of fine-tuning or RAG? | Prompt engineering when: (1) Task is simple classification/formatting, (2) No training data or changing knowledge base, (3) Need rapid iteration/testing, (4) Budget constraints prohibit training. Exam tip: Start with prompting, escalate to RAG/fine-tuning only if needed. |
| 10 | What is the trade-off between DBRX and Llama 3.1 405B on Databricks? | DBRX: Lower latency (~2-3x faster), lower cost, excellent instruction following, sufficient for most tasks. Llama 405B: Highest reasoning capability, best for complex multi-step problems, much higher latency/cost. Exam tip: Use 405B only when DBRX demonstrably insufficient. |
| 11 | How do you ensure an LLM outputs valid JSON on Databricks? | Use response_format parameter in Model Serving API with JSON schema definition. Model guarantees output matches schema, no post-processing needed. Alternative: structured output via function calling. Exam tip: response_format is preferred over prompt instructions + parsing. |
| 12 | What memory component should an agent have for multi-turn conversations? | Conversation memory stores: (1) Previous user messages, (2) Agent responses, (3) Tool call results, (4) Intermediate reasoning (optional). Enables context continuity across turns. Exam tip: Stateful conversations = memory component required; stateless batch = no memory needed. |
