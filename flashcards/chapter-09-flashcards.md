## Chapter 9: Evaluation and Monitoring of GenAI Applications — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What does the faithfulness metric measure in RAG evaluation? | Whether the generated answer only uses information present in the retrieved context (no hallucination). Exam tip: Faithfulness = anti-hallucination metric. Requires retrieved_context column in eval dataset. |
| 2 | Context precision vs context recall - what's the difference? | Context precision: are retrieved chunks ranked correctly (relevant ones first)? Context recall: are all relevant chunks retrieved (coverage)? Exam tip: Precision = ranking quality, Recall = completeness. Both are retrieval metrics. |
| 3 | What columns does mlflow.evaluate() require for computing faithfulness with LLM-as-a-judge? | question, generated_answer, retrieved_context. Exam tip: ground_truth NOT needed for faithfulness (only for answer correctness). Faithfulness compares answer to context, not to ground truth. |
| 4 | How do Databricks inference tables enable production monitoring? | Model Serving automatically logs all requests/responses to a Delta table. Use Lakehouse Monitoring on this table to track quality metrics, data drift, and model drift. Exam tip: Inference tables = production logging, Lakehouse Monitoring = drift detection. |
| 5 | Offline vs online evaluation - what's the difference? | Offline: evaluate on static test dataset before deployment. Online: sample live production traffic and score it. Exam tip: Online catches production distribution shift that offline misses. Use inference tables for online eval. |
| 6 | What is LLM-as-a-judge evaluation? | Using a strong LLM (GPT-4, DBRX) to score outputs on custom criteria. Makes API call per example. Exam tip: Primary cost driver is LLM API calls, not compute. More flexible than rule-based metrics. |
| 7 | What does answer relevance metric measure? | Does the answer address the user's question? Exam tip: Different from faithfulness (which checks grounding in context). Answer can be relevant but unfaithful (hallucination), or faithful but irrelevant (doesn't answer question). |
| 8 | When would you choose a smaller model over a larger model for RAG? | High-volume scenarios with latency requirements and cost constraints. Exam tip: 7B models = faster (200ms), cheaper ($0.001/1K tokens), less accurate. 70B models = slower (800ms), expensive ($0.02/1K tokens), more accurate. Trade-off: cost/latency vs accuracy. |
| 9 | What does context recall = 0.6 indicate? | Only 60% of relevant chunks are retrieved; 40% are missed. Exam tip: Low recall = poor coverage, not ranking. Fix: adjust retrieval parameters, improve embeddings, increase chunk count. |
| 10 | What does context precision = 0.9 indicate? | Retrieved chunks are well-ranked (relevant ones appear first). Exam tip: High precision = good ranking. If precision drops but recall stable → irrelevant chunks ranked too high (vector index drift). |
| 11 | How to implement online evaluation with mlflow.evaluate()? | 1) Enable inference tables on Model Serving to log production traffic to Delta. 2) Sample logged requests/responses. 3) Run mlflow.evaluate() on sampled data. Exam tip: Inference tables bridge production to evaluation. |
| 12 | What are the 4 core RAG-specific metrics tested on the exam? | 1) Faithfulness (no hallucination), 2) Answer relevance (addresses question), 3) Context precision (ranking), 4) Context recall (coverage). Exam tip: Precision/recall = retrieval quality. Faithfulness/relevance = generation quality. |
